# 油品配送调度台

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 引擎行为验证：`npm run verify`

## 设计说明：带版本凭据的调度台

旧版实现把整份配送单数组存在一个 localStorage key 中，每次保存整体覆盖，
会丢失并发窗口的罐容占用，且页面中途关闭可能留下“半份单 + 半份台账”。
现按**事件溯源 + 乐观版本控制**重构（`src/dispatch/`）：

### 库存生命周期

- `预占`：派车前从油库可用吨数（总罐容 − 占用中 − 已到站核销）中预扣，超量拒绝。
- `装车核销`：已预占 → 已装车，占用保留。
- `发车`：已装车 → 在途。
- `确认到站`：在途 → 已到站，吨数真正核销出库，可用量不回升。
- `撤单`：仅已预占可撤，预占吨数释放回可用量。
- `在途失败`：已装车/在途单失败，占用吨数释放。

### 版本凭据与并发

- 所有状态都由只追加的提交日志（`hxwlfront-19-dispatch-log`）推导，永不原地覆盖。
- 每次提交携带所依据的 `expectedVersion`；提交前同步重读磁盘日志，
  磁盘版本已被其它窗口推进时返回 `conflict`，并先把对方的提交追加进本窗口
  （监听 `storage` 事件做实时同步）。
- 冲突时后提交者的**草稿原样保留**（`src/dispatch/draft.ts`，按标签页独立槽位存储，
  页面关闭重开也可恢复），界面提示所选油品的可用量变化，一键以新版本刷新后重试。
- 每次提交只做一次 localStorage 写入：要么完整可见，要么停留在上一版本，不会各留一半。
- 订单上保留预占/装车版本号与完整状态凭据链，可展开查看；另有版本审计日志表。

### 旧版配送单一次性迁移

- 首次启动若发现旧 key `hxwlfront-19-oil-delivery`，先落账油库罐容，
  再把旧单按条映射为新台账事件（运输中→在途、已到站→已核销、其余→已预占，坏数据跳过）。
- 每条旧单独立原子提交；迁移中断重开时，断点完全由事件日志推导：
  已落账的条目幂等跳过，只继续未完成条目，不会重复扣减。
- 全部完成后旧 key 改名归档移除，迁移状态本身由“旧 key 是否存在”判定。

页面底部“场景演示”可模拟并发窗口抢占与旧版数据迁移；`scripts/verify-engine.ts`
覆盖占用口径、撤单/失败释放、超量拒绝、乐观冲突、磁盘抢占、迁移断点续跑等场景。

# 油罐车配送调度台（版本化台账）

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 测试：`npm test`（Node 内置测试器 + esbuild 打包，无需额外测试框架）

数据仍保存在浏览器 localStorage，但从“整份覆盖的配送单数组”改成了**带版本凭据的台账**，
解决三个老问题：并发安排同一油品互相冲掉占用、页面中途关闭留下半份数据、旧版数据迁移重复扣减。

## 罐容生命周期

- **派车前预占**：新建配送单为「待装车」，从该油品可用吨数中预占；可用吨数不足直接拒绝，不产生任何写入。
- **装车核销**：「待装车 → 运输中」，占用类别由预占转为在途，总占用不变。
- **撤单**：「待装车 → 已撤单」，立即释放预占。
- **在途失败**：「运输中 → 在途失败」，立即释放在途占用。
- **确认到站**：「运输中 → 已到站」，转为已交付占用。

占用完全由单据状态投影得出（`fuelView`），没有可被覆盖的“余量字段”。

## 版本凭据（乐观锁）

- 台账有单调递增的 `version`，初始为 v1，每笔成功提交 +1。
- 提交必须携带读取时的版本凭据：
  - 凭据落后（别的窗口已提交）→ `VersionConflictError`，本窗口台账即时刷新，
    表单草稿保留，页面提示「台账占用已变化」，用户按最新罐容一键继续；
  - 业务不合法（罐容不足、非法流转）→ 拒绝且版本不前进。
- 跨窗口通过 `storage` 事件即时同步；同窗口写入经 Promise 队列串行化。

## 崩溃恢复（两阶段 WAL）

localStorage 中两个键：

- `hxwlfront-19-dispatch-ledger-v2`：已提交台账快照；
- `hxwlfront-19-dispatch-wal-v2`：提交凭据信封（先于快照写入）。

提交顺序：写 WAL → 写快照 → 删 WAL。崩在任意一步，重开 `bootstrap` 都会
补提交或清理残留，单据与台账同进同退，不会各留一半。

## 旧版数据一次性迁移

- 数据源：旧键 `hxwlfront-19-oil-delivery`；无旧键时使用旧版内置种子（与旧行为一致）。
- 迁移单使用确定性 id `mig-<源指纹>-<序号>`，单据与迁移检查点在**同一个台账事务**落账。
- 迁移中断（页面关闭）后重开只继续检查点之后的部分；已落账单据靠确定性 id 跳过，
  罐容只扣一次。两个窗口并发迁移时，后提交者靠版本冲突重试并跳过对方已落账部分。
- 全部完成后旧键改名归档为 `hxwlfront-19-oil-delivery.archived`（留存但不再作为数据源）。
- 无效旧数据（油品/吨数不合法）只推进检查点，不生成单据、不扣减罐容。

## 目录

- `src/dispatch/engine.ts`：领域模型、状态机、罐容投影、事务校验（纯函数）
- `src/dispatch/storage.ts`：版本化提交、WAL 两阶段与启动恢复
- `src/dispatch/migration.ts`：旧版数据一次性/断点续传迁移
- `src/dispatch/store.ts`：Pinia store（提交队列、跨窗口同步、草稿留存）
- `src/dispatch/dispatch.test.ts`：预占/释放、乐观并发、WAL 崩溃恢复、迁移幂等等测试
